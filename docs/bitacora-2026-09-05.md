## 1. El login no era un problema de configuración

descartó con evidencia directa:

  `VITE_SUPABASE_URL` y `VITE_SUPABASE_ANON_KEY` correctos — se comparó byte a
  byte contra el anon key real que Rocco pegó desde el dashboard de Supabase

  un typo de transcripción, no un proyecto distinto).
- Se instaló un interceptor de `fetch` en el navegador para capturar la
  respuesta real del intento de login. El request va exactamente a
  `https://xfnywkwocszfcrukikkb.supabase.co/auth/v1/token?grant_type=password`
  y responde `400 {"code":"invalid_credentials","message":"Invalid login
  credentials"}` — GoTrue rechazando el par email+contraseña contra el
  proyecto correcto. No hay bug de config: la contraseña que Rocco tenía
  anotada no era la que estaba guardada (o nunca se había seteado una).

**Importante para no repetir el diagnóstico**: en Vercel (proyecto
`plataforma-crm`, Settings → Environment Variables) siguen sin existir

del backend sin prefijo `VITE_` (`SUPABASE_URL`, `SUPABASE_ANON_KEY`, etc.,

que se carguen esas tres variables en Vercel. No se tocó esto todavía — ver

## 2. Bug nuevo, real: falta el rewrite de SPA en Vercel

Cualquier navegación **directa** (hard nav, no click dentro de la SPA ya
cargada) a una ruta que no sea `/` da `404: NOT_FOUND` de Vercel — `/login`,
`/reset-password#...`, `/qr`, probado en vivo. Causa: no existe ningún
`vercel.json` (ni en la raíz del repo ni en `frontend/`) con un rewrite
catch-all a `index.html`. El proyecto usa `createBrowserRouter` de
react-router-dom (`frontend/src/app/router.tsx`), que depende 100% de que el
server devuelva `index.html` para cualquier ruta y deje el routing al
cliente.

Esto **no es hipotético**: fue lo que rompió el link de reset de contraseña
real que le llegó a Rocco por mail (`.../reset-password#access_token=...`
→ 404 en Chrome). Se resolvió con un workaround manual desde el navegador de
Claude para esta vez puntual: navegar a la raíz **con el hash del token ya en
la URL** (`https://plataforma-crm-chi.vercel.app/#access_token=...&type=recovery`,
nunca a `/reset-password` directo) para que `supabase-js` alcance a correr
`detectSessionInUrl` en la carga inicial, y desde ahí navegar client-side
(`pushState`) a `/reset-password` una vez que la sesión ya estaba
establecida. Funcionó, pero es un workaround — cualquier usuario real que
reciba un link de reset (o cualquier link profundo) se va a encontrar con el
mismo 404 hasta que se aplique el fix real.

**Fix pendiente** (no aplicado esta sesión — ver por qué en pendientes):
agregar `frontend/vercel.json` (la Root Directory del proyecto en Vercel es
`frontend`, confirmado en Settings → Build and Deployment):

```json
{
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

Vercel resuelve archivos estáticos reales antes que los rewrites, así que
esto no rompe `/assets/*` ni nada servido físicamente — solo cubre las rutas
que hoy no tienen archivo y deberían caer en el router de React.

### 3.1 Nota aparte: el flujo de "Enviar QR" por mail

Rocco probó el botón "Enviar" → "Abrir email" del QR de prueba y le abrió una
pestaña nueva en blanco (`mailto:...`) sin hacer nada. No es un bug: Windows
no tiene un cliente de correo asociado a links `mailto:`, y el propio código
ya lo previó (`frontend/src/lib/sendQr.ts`, comentario "Hallazgo 2 / DEL-020,
Cycle 23" — falla en silencio quo el dispositivo no tiene cliente de correo
por defecto). El diálogo tiene un botón "Copiar mensaje" pensado exactamente
para este caso — copia el mismo asunto+cuerpo como texto plano para pegar en
Gmail/Outlook web. No requiere ningún cambio de código.

### 3.2 Detalle menor sin resolver: UI muerta en el diálogo de creación de QR

El diálogo "Generar QR digital" todavía muestra un radio "Tipo de QR:
Reusable / Un solo uso", pero el backend eliminó `qrType` por completo del
schema de creación en PR #154 (`createDigitalQrSchema` no tiene ese campo —
ver comentario en `src/controllers/qr.controller.ts`). No rompe nada (Zod
descarta el campo extra en silencio), pero es UI que miente sobre una opción
que ya no existe. Candidato a limpiar en el mismo PR del punto 2, o en uno
